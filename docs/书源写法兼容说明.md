# iread 书源写法兼容说明

> 面向：会写 CSS / XPath / JSONPath，但没写过「阅读（Legado）3.0」书源的人。  
> 依据：本仓库代码，不是阅读官方文档。行号形如 `legado.js:493` 指 `ireader-2.3.10/renderer/js/sources/` 下的文件。  
> 我们的实现是 Legado 的一个**子集**，而且有自己的一批坑。凡标「未在本实现中确认」的，就是我没能在代码里找到依据的部分，请勿当成承诺。

四个文件的分工，看懂的这部分心里就有底了：

| 文件             | 职责                                                                                                      |
| -------------- | ------------------------------------------------------------------------------------------------------- |
| `rule.js`      | 规则求值：切分（`&&` `\|\|` `%%`）、选择器（JSoup 简写 / CSS / XPath / JSONPath）、`##` 净化、`{{}}` 模板、`@put`/`@get`、URL 编码 |
| `legado.js`    | 书源流程：导入归一化 `normalize()`、发请求、search / explore / detail / catalog / content                              |
| `legacy-js.js` | `@js:` / `<js>` / `{{}}` 里那个 JS 沙箱（`java.*` 就在这里）                                                       |
| `index.js`     | 书源 JSON 导入、库管理、筛选（`deepTest`）                                                                           |

一个容易忽略的执行事实：WebView2 版里 `search / explore / detail / catalog / content` 并不在渲染进程跑，而是经 `bridge.runSourceTask` 送进**独立书源进程**（`source-runtime.js:10-21`）；拿不到这个桥时报 `code='UNSUPPORTED'`（`source-runtime.js:12-14`）。书源级 `timeout` 会被钳到 **1s–30s**（`source-runtime.js:16`），超过 30s 的部分没有意义。

## 1. 一分钟上手

下面这份 JSON 是**最小可用**的搜索型书源，字段名全部是我们认的名字，可直接抄改。假设目标站点是 `https://www.example.com`，搜索页是 `/search?q=关键词&page=1`，结果是 `.result-list li` 里的 `h3 > a`。

```json
{
  "bookSourceName": "示例站",
  "bookSourceUrl": "https://www.example.com",
  "bookSourceType": 0,
  "enabled": true,
  "bookSourceCharset": "utf-8",
  "timeout": 15000,
  "header": "{\"User-Agent\":\"Mozilla/5.0 (Linux; Android 10) AppleWebKit/537.36 Chrome/120 Mobile Safari/537.36\"}",
  "searchUrl": "/search?q={{key}}&page={{page}}",
  "ruleSearch": {
    "bookList": ".result-list li",
    "name": "h3 a@text",
    "author": ".author@text",
    "bookUrl": "h3 a@href",
    "coverUrl": "img@src",
    "intro": ".intro@text",
    "lastChapter": ".last@text"
  },
  "ruleBookInfo": {
    "name": "#info h1@text",
    "author": "#info .author@text",
    "intro": "#intro@text",
    "coverUrl": "#info img@src",
    "tocUrl": "#info a.catalog@href"
  },
  "ruleToc": {
    "chapterList": "#list dd",
    "chapterName": "a@text",
    "chapterUrl": "a@href"
  },
  "ruleContent": {
    "content": "#content"
  }
}
```

逐字段一句话：

- `bookSourceName` / `bookSourceUrl`：名称与站点根地址。两个都缺会直接导入失败（`legado.js:112`）；地址同时用作**相对地址基准**和请求的 `referer`（`legado.js:302`）。
- `bookSourceType`：`0` 文字源；非 0（如 `4` 视频源）只影响筛选时「正文算不算有效」的判定（`legado.js:131`、`index.js:768`、`index.js:1452`）。
- `enabled`：只有显式写 `false` 才是禁用（`legado.js:124`），不写等于启用。
- `bookSourceCharset`：响应解码用的字符集，只认 utf-8 / gbk / gb2312 / gb18030 / big5 / shift_jis / euc-jp / euc-kr / iso-8859-1 / windows-1252（`rule.js:1688`）。
- `timeout`：毫秒，缺省 15000（`legado.js:129`），最终被钳到 1–30s（`source-runtime.js:16`）。
- `header`：请求头，JSON 字符串（也接受 `@js:` / `<js>` 形态，见 §2）。
- `searchUrl`：搜索地址模板，`{{key}}` 是关键词、`{{page}}` 是页码（`legado.js:491`、`rule.js:1481`）。
- `ruleSearch.bookList`：结果条目的选择器；每条再取 `name` / `bookUrl` 等子规则。
- `ruleSearch.name` / `bookUrl`：**必须有值**，否则这条结果被跳过（`legado.js:538`）；不写 `name` 默认 `@text`，不写 `bookUrl` 默认 `a@href`（`legado.js:534-536`）。
- `ruleBookInfo.tocUrl`：详情页上「目录页」的地址；不写或解析出文字而非链接时，退回当前页当目录页（`legado.js:836-840`）。
- `ruleToc.chapterList`：目录条目；`chapterName` 默认 `@text`，`chapterUrl` 默认 `a@href`（`legado.js:954-956`）。
- `ruleContent.content`：正文。写 `#content`（元素）比写 `#content@text` 更好，元素会被逐段转成带换行的纯文本（`rule.js:1915-1921`）。

## 2. 书源 JSON 字段表

所有字段都由 `legado.js` 的 `normalize(raw)`（`legado.js:107`）读取。**它只返回一张固定字段表**——JSON 里写了别的键，会被直接丢掉，不报错。

### 2.1 顶层字段

| 字段                  | 也接受                 | 我们怎么读它           | 必填    | 备注 / 依据                                                               |
| ------------------- | ------------------- | ---------------- | ----- | --------------------------------------------------------------------- |
| `bookSourceUrl`     | `url`、`sourceUrl`   | 站点根地址            | **是** | `legado.js:110`；用作相对地址基准（`legado.js:239`）与 referer（`legado.js:302`）   |
| `bookSourceName`    | `name`、`sourceName` | 显示名              | **是** | `legado.js:111`；缺失时用地址兜底                                              |
| `bookSourceGroup`   | —                   | **不读，被丢弃**       | 否     | `legado.js:122` 直接写 `group: ''`；导入后源没有分组，只能在软件内手动分组                   |
| `bookSourceType`    | —                   | 数字，`0` 文字、`4` 视频 | 否     | `legado.js:131`；只用于筛选正文判定，不影响解析本身                                     |
| `bookSourceCharset` | `charset`           | 响应解码字符集          | 否     | `legado.js:125`；取值表见 `rule.js:1688`                                   |
| `requestCharset`    | —                   | 请求侧字符集           | 否     | `legado.js:126`、`legado.js:295`                                       |
| `lenientDecode`     | —                   | 宽松解码，只认 `true`   | 否     | `legado.js:127`（`=== true`）                                           |
| `enabled`           | —                   | 是否启用             | 否     | `legado.js:124`；`!== false`                                           |
| `header`            | `headers`           | 请求头              | 否     | `legado.js:128`，求值见 `evalHeaders`（`legado.js:389`）                    |
| `timeout`           | —                   | 毫秒               | 否     | `legado.js:129`，缺省 15000，钳 1–30s                                      |
| `jsLib`             | —                   | 全局 JS 库          | 否     | `legado.js:133`；注入方式见 §5                                              |
| `searchUrl`         | `search`            | 搜索地址模板           | 搜索源必填 | `legado.js:134`；缺失时搜索报 `NO_RULE`（`legado.js:490`）                     |
| `exploreUrl`        | —                   | 发现页分类            | 发现源必填 | `legado.js:135`；三种写法见 §4.2                                            |
| `ruleSearch`        | —                   | 搜索规则对象           | 搜索源必填 | `legado.js:136`；必须是对象或**严格 JSON 字符串**（`ruleContainer`，`legado.js:94`） |
| `ruleExplore`       | —                   | 发现规则对象           | 否     | 不写则发现页回退用 `ruleSearch`（`legado.js:628-629`）                           |
| `ruleBookInfo`      | —                   | 详情规则对象           | 否     | 不写则详情字段全空，但书名为空时会退回页面 `<title>`（`legado.js:841-844`）                  |
| `ruleToc`           | —                   | 目录规则对象           | **是** | 缺 `chapterList`/`list` 报 `NO_RULE`（`legado.js:898`）                   |
| `ruleContent`       | —                   | 正文规则对象           | **是** | 缺 `content`/`text` 报 `NO_RULE`（`legado.js:1064`）                      |

**字段名写错在我们这里是静默失效**：`normalize` 不校验未知键，也不校验拼写。把 `ruleToc` 写成 `ruleTocs`，结果是导入成功、筛选报「目录规则没配置」或直接 `EMPTY_TOC`，而不是「JSON 有错」。

### 2.2 `ruleSearch`

| 键                                  | 缺省           | 依据                                           |
| ---------------------------------- | ------------ | -------------------------------------------- |
| `bookList`                         | 可用 `list` 代替 | `legado.js:493`                              |
| `name`                             | `@text`      | `legado.js:534`                              |
| `bookUrl`                          | `a@href`     | `legado.js:535`；结果会自动补成绝对地址（`legado.js:537`） |
| `coverUrl`                         | —            | `legado.js:539`，同样补绝对地址（`legado.js:545`）     |
| `author` / `intro` / `lastChapter` | —            | `legado.js:542-544`                          |

一条结果必须**同时**有书名和详情页地址，否则被丢弃（`legado.js:538`）。

### 2.3 `ruleExplore`

键与 `ruleSearch` 相同（`bookList` 也可写 `list`），另外：

- `ruleExplore` 里只要有 `bookList`/`list`，就用它；否则整块回退到 `ruleSearch`（`legado.js:628-629`）。
- 发现页每条**只产出书名、作者、详情页地址**三项（`legado.js:701`）——写 `coverUrl` / `intro` / `lastChapter` 在发现页不会被使用。

### 2.4 `ruleBookInfo`

| 键                           | 说明                                  | 依据                              |
| --------------------------- | ----------------------------------- | ------------------------------- |
| `init`                      | 详情页预处理，可写 `@js:` / `<js>` / `{{…}}` | `legado.js:819`、`legado.js:740` |
| `name` / `author` / `intro` | 书名 / 作者 / 简介                        | `legado.js:825-827`             |
| `coverUrl`                  | 封面，自动补绝对地址                          | `legado.js:828-830`             |
| `lastChapter`               | 最新章节名                               | `legado.js:831`                 |
| `wordCount`                 | 字数                                  | `legado.js:832`                 |
| `tocUrl`                    | 目录页地址                               | `legado.js:833-840`             |

`init` 会**先于所有字段**执行（`legado.js:817-823`），它的作用是把整页「收窄/换形」，例如 JSON 接口用 `init: "$.data"` 把 `{code,msg,data}` 拆到 `data`（`legado.js:721-727`）。

### 2.5 `ruleToc` 与 `ruleContent`

| 键                               | 缺省       | 依据                                         |
| ------------------------------- | -------- | ------------------------------------------ |
| `ruleToc.chapterList`（或 `list`） | 必填       | `legado.js:897-898`                        |
| `ruleToc.chapterName`           | `@text`  | `legado.js:954`                            |
| `ruleToc.chapterUrl`            | `a@href` | `legado.js:955`；空地址的章节被跳过（`legado.js:957`） |
| `ruleToc.nextTocUrl`            | —        | `legado.js:965-977`，**只取第一个地址**            |
| `ruleContent.content`（或 `text`） | 必填       | `legado.js:1063-1064`                      |
| `ruleContent.nextContentUrl`    | —        | `legado.js:1126-1157`，**支持多地址**            |

章节名解析不出时自动命名「第 N 章」（`legado.js:958`）；目录最后按地址去重（`legado.js:1001-1007`）。

### 2.6 被丢弃的字段（写了也没用）

`legado.js:107-176` 只搬运上面那张表。以下常见 Legado 字段在这里**不会被读取**：`bookSourceGroup`、`concurrentRate`、`loginUrl`、`loginCheckJs`、`loginUi`、`isVip`、`variableComment`、`respondTime`、`lastUpdateTime`、`customOrder`、`maxTocPages`、`ruleSearch.checkKeyWord`。其中两条值得单独说：

- `concurrentRate` / `isVip` / `loginCheckJs`：连字段都没有，谈不到限速与登录态；
- `maxTocPages`：`catalog()` 读的是 `src.maxTocPages || 20`（`legado.js:903`），但 `normalize` 不保留这个键，所以**目录永远最多 20 页**；正文同理写死 10 页（`legado.js:1073`）。

### 2.7 简化写法（`rules` 一个对象搞定）

`normalize` 有一条省事的备用分支（`legado.js:150-176`）：用一个 `rules`（或 `rule`）对象平铺所有规则，我们替你映射成标准结构。

```json
{
  "name": "极简示例",
  "url": "https://www.example.com",
  "searchUrl": "/search?q={{key}}",
  "rules": {
    "list": ".result-list li",
    "name": "h3 a@text",
    "author": ".author@text",
    "url": "h3 a@href",
    "cover": "img@src",
    "intro": ".intro@text",
    "lastChapter": ".last@text",
    "detailName": "#info h1@text",
    "detailIntro": "#intro@text",
    "tocUrl": "#info a.catalog@href",
    "chapterList": "#list dd",
    "chapterName": "a@text",
    "chapterUrl": "a@href",
    "nextTocUrl": "a.next@href",
    "content": "#content",
    "nextContentUrl": "a.next-page@href"
  }
}
```

映射关系（`legado.js:152-175`）：`list`→`bookList`、`url`→`bookUrl`、`cover`→`coverUrl`、`chapters`→`chapterList`、`text`→`content`、`detailName`/`detailIntro` 覆盖详情页取值。

**触发条件很关键**：`legado` 标记是 `!!(raw.bookSourceUrl || raw.ruleSearch || raw.ruleToc)`（`legado.js:118`）。一旦你写了 `bookSourceUrl` 或 `ruleSearch`，简化分支就**不会**走——地址请改用 `url` 或 `sourceUrl` 键。这也是为什么上面例子里地址写的是 `"url"`。

简化写法没有 `init`、没有 `wordCount`、也没有独立的 `ruleExplore`（发现页会回退用 `rules` 映射出来的 `bookList`）。要做复杂源，还是用标准结构。

## 3. 规则方言

一条规则字符串的求值入口是 `rule.js` 的 `parseSourceText()`（`rule.js:987`）+ `evalList()`（`rule.js:1252`，取列表）/ `evalString()`（`rule.js:1189`，取字符串）。

### 3.1 前缀：决定用哪个引擎

判定顺序照抄（`rule.js:994-999`）：`@CSS:` → `@@` → `@XPath:` → `@Json:` → `$.`/`$[` → `//` 开头。

| 写法          | 引擎                  | 正例                                       | 反例与我们的处理                                                                                                                          |
| ----------- | ------------------- | ---------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| 不写前缀        | JSoup 简写（多级用 `@` 连） | `div.item@a@href`                        | `div@a b@href` —— `@` 切开后 `a b` 被当成一个 CSS 后代选择器，会跨层级抓节点，和「逐级」语义不同（`rule.js:512-526`、`rule.js:426-429`）                            |
| `@CSS:`     | 真 CSS，尾部 `@取值`      | `@CSS:.item h3@text`                     | `@CSS:.item` + 取值写在前端 `@CSS:@text.item` → `lastIndexOf('@')` 取最后一个 `@`，选择器变成 `@text.item`，语法非法 → `SELECTOR` 错误（`rule.js:501-506`） |
| `@@`        | 去掉前缀，强行按简写/无前缀处理    | `@@div.item@text`                        | `@@@CSS:.x` → 只剥一次 `@@`，剩下 `@CSS:.x` 又会被当简写（`@` 是分隔符）→ 空                                                                          |
| `@XPath:`   | `document.evaluate` | `@XPath://div[@class="item"]/h3/a/@href` | 写 `@Xpath:` 也认（大小写不敏感，`rule.js:996`）；但 `xpath:`、`XPATH:` 不带 `@` → 当 CSS 选择器 → 0 命中                                                |
| `@Json:`    | JSONPath 子集         | `@Json:$.data.list[*].name`              | `@json:$.x` 认（`rule.js:997` 大小写不敏感）；`json:$.x` 不认 → 当 CSS → 空                                                                     |
| `$.` / `$[` | 同上，可省 `@Json:`      | `$.data.list[*].title`                   | `$data.list`（少点）→ 当 CSS → 空                                                                                                       |

额外便利：**内容本身是 JSON 时，无前缀规则自动升级为 Json 模式**（`rule.js:1015-1018`），所以 `init` 之后写 `data.name` 也行；但万一页面是 HTML，这条规则就会被当 CSS。

### 3.2 JSoup 简写糖

每一级只认这五种形式（`rule.js:407`）：`children`、`class.X`、`tag.X`、`id.X`、`text.X`，其余一律当 CSS 选择器（`rule.js:426-429`）。

| 写法                        | 含义                                  | 依据                |
| ------------------------- | ----------------------------------- | ----------------- |
| `children` / `children.0` | 直接子元素                               | `rule.js:410-411` |
| `class.item`              | `.item`；多个类写 `class.a b` 会转成 `.a.b` | `rule.js:412-413` |
| `tag.div`                 | 标签名                                 | `rule.js:415-416` |
| `id.main`                 | `[id="main"]`，找不到时若当前节点 id 相符则取自己   | `rule.js:417-420` |
| `text.关键字`                | 自身文本含关键字的**所有后代**                   | `rule.js:421-425` |

**取值后缀**只有 5 个关键字（`rule.js:450`）：`@text`、`@textNodes`、`@ownText`、`@html`、`@all`。除它们之外的 `@xxx` 一律当**属性名**取 `getAttribute`（`rule.js:479-484`），所以 `@href`、`@src`、`@data-id`、`@title` 都能用（这正是 Legado 的做法，不是一个白名单）。


- `@html` 与 `@all` 行为相同：去 script/style 后 outerHTML 拼接（`rule.js:470-478`）。
- `@text` 是 jsoup `text()` 语义：script/style 内容不算、块级元素之间补空格（`rule.js:149`、`rule.js:455-459`）。
- `@textNodes` 是每个文本节点 trim 后用 `\n` 连接（`rule.js:93`）。
- `@ownText` 只取直接文本、**不插空格**（`rule.js:81`）。

**正例**：`div.book-item@h3@a@href`  
**反例**：`div.book-item h3 a@href` —— 前三级被当成一个 CSS 选择器串，因为 `@` 只有一处，`div.book-item h3 a` 会被 `querySelectorAll` 接受（能跑，但语义和你以为的「逐级」不同）；真正会出事的是 `div@a b@href`：`a b` 会被当后代选择器，跨层级抓节点。

单段规则有一个放宽：`name: "h3"` 在取字符串时会自动取 `text`（`rule.js:589-593`），而 Legado 要求显式 `@text`。

### 3.3 索引：`.N`、`!N`、`[a,b]`

索引写在**某一级的末尾**（`rule.js:298-350`）：

| 写法                           | 含义                                                         |
| ---------------------------- | ---------------------------------------------------------- |
| `div.item.0` / `div.item.-1` | 第 1 个 / 最后一个（负索引 = `len+n`，`rule.js:352` 起）                |
| `div.item!0`                 | 排除第 0 个，返回剩下的                                              |
| `div.item[0,2,-1]`           | 取多个                                                        |
| `div.item[!0]`               | 排除第 0 个                                                    |
| `div.item[0:5]` / `[0:10:2]` | 区间（可带步长），`rule.js:315-321`                                 |
| `tag.div.-1:10:2`            | 老写法：`:` 只是「再要一个索引」的二级分隔符，等于取 -1、10、2 三个（`rule.js:338-346`） |

注意 `:N` **不是切片**（`rule.js:338` 注释明确）。越界会被钳制，不会报错：单个索引超出范围就丢弃（`rule.js:375-377`），区间端点会被夹到 `0..len-1`（`rule.js:361-366`）。

区间的 `end` 是**闭区间**（`for (i = start; i <= end; i += step)`，`rule.js:369-373`），所以 `[1:3]` 是下标 1、2、3 三个，`[0:-1]` 是全部。

**正例**：`#list dd.-1@a@href`（最后一个章节）、`#list dd[0:9]`（前 10 章）  
**反例**：`#list dd.99@a@href`（以为越界会报错、或自动取最后一个）——单索引超出范围就**静默丢弃**，结果是空列表，最终表现为 `EMPTY_TOC`，看不出是索引写错了（`rule.js:375-377`）。

### 3.4 连接符 `&&`、`||`、`%%`

切分函数是 `splitRule(str, delims)`（`rule.js:245`）：**取最先出现的那个分隔符**，之后只按它切。

| 连接符    | 语义                                            | 依据                |
| ------ | --------------------------------------------- | ----------------- |
| `&&`   | 各段结果**拼接**                                    | `rule.js:542-544` |
| `\|\|` | 取**第一个非空**段，后面的不再看                            | `rule.js:529-532` |
| `%%`   | 按**第一段**的长度交错合并（Legado 用 `results[0]` 的长度做基准） | `rule.js:533-541` |

**最大的坑**：三种不能混用。`"a||b&&c"` 里最先出现的是 `||`（`rule.js:257-266`），于是整串被切成 `["a", "b&&c"]`，第二段里的 `&&` 会留在选择器里 → 0 命中。

**正例**：`.item||.book-item||li.book`（备选选择器，先命中先用，页面改版也能活）  
**反例**：`h3@text||h4@text&&.note@text`

### 3.5 `##正则##替换` 净化与 `###`

- 语法：`规则##正则##替换`；结尾再加 `#` 即 `###` 表示「只处理第一个」（`rule.js:1144-1167`）。
- Java 正则会被翻译成 JS：内联 `(?i)(?s)(?m)`、`\Q…\E`、占有量词、`\p{IsXxx}`（`rule.js:1073`）；替换串里的 `\1` 会翻成 `$1`（`rule.js:1106`）。
- 编译失败不会报错，退化成**字面量替换**，只在控制台 warn（`rule.js:1168-1175`）。

**`###` 的真实行为要注意**：它不是「整串里只替换第一次」，而是先 `exec` 出第一个匹配，然后**只返回这一段匹配文本**（替换后）——`rule.js:1162-1166` 的 `return m ? m[0].replace(...) : ''`。也就是说 `"封面：xxx 简介：yyy"##简介：##` 用 `###` 会只剩匹配到的那一小段，前面的「封面：xxx」被丢掉。

**正例**：`intro@text##\\s*&nbsp;\\s*##`（全局清空白）  
**反例**：`intro@text##^作者：.*$###`（以为「只删第一处，其余保留」）→ 实际返回的是被匹配的那一段本身；替换成空就是**空串**，整段简介直接没了。想删指定片段就别加 `###`。

**关键限制**：`##` 只在**取字符串**的路径生效（`rule.js:1246`）。列表规则（`bookList`、`chapterList`）走 `evalList`，那里只把 `##` 之前的部分当选择器（`rule.js:1272-1273`）、**不执行替换**。所以在 `bookList` 上写 `##` 净化是静默无效的。

**正例**：`name` 写 `h3@text##\\s*最新章节.*$`  
**反例**：`bookList` 写 `.item##^广告$` → 选择器变成 `.item`，后面整段被忽略，净化不生效

### 3.6 `{{…}}` 模板

规则内的 `{{…}}` 由 `makeUpRule()` 逐字符展开（`rule.js:931`）。大括号里如果是**规则**形态（以 `@`、`$.`、`$[`、`//` 开头，`rule.js:851`）就走规则求值，否则当 **JS 表达式**求值（`rule.js:903`）。

一个必须知道的行为：**含 `{{…}}` 且 `{{` 之前没有 `##` 时，插值结果直接当最终答案，不再二次求值**（`rule.js:873`、`rule.js:1215`，对齐 Legado 强制 Regex 模式）。

**正例**：`tocUrl` 写 `{{$.data.catalogUrl}}`  
**反例**：`name` 写 `{{$.prefix}}h1@text` —— 插值后整串被当答案返回，`h1@text` 不会被再解析，你会得到形如 `xxxh1@text` 的垃圾字符串

### 3.7 `@put:{…}` / `@get:{…}`

- 写变量：`rule` 里任意位置出现 `@put:{"k":"v"}` 会被摘出来，值本身可以是一条规则（`rule.js:1003`、`rule.js:1274-1276`）。裸键（不带引号）也能解析。
- 读变量：`@get:{k}`（`rule.js:940-947` 解析、`rule.js:966-969` 取值）；取不到返回**空串**。注意 `{{k}}` 里的 `k` 是 **JS 标识符**，不是变量名，读变量必须用 `@get:{k}` 的写法。
- 存放位置是 `ctx.source.__vars`，即**同一个书源对象上**（`rule.js:960-964`），所以变量跨字段、跨页面共享（`source-runtime.js:26-28` 会把它回写）。
- 空值/值为 `null` 时 `@get` 拿不到，会返回空串。

**正例**：`init` 里 `@put:{"host":"{{$.host}}"} $.data` 之后用 `@get:{host}` 拼地址  
**反例**：`@put:{"a":{"b":1}}`（嵌套对象）—— 正则只匹配到第一层 `{…}`（`rule.js:1003` 的 `\{[^}]+?\}`），嵌套会解析失败，变量**静默丢失**

### 3.8 `##` 与 `{{…}}` 的先后顺序

一条规则里同时有 `##` 和 `{{…}}` 时，找 `##` 切点的函数会**跳过 `{{…}}` 内部**（`headBeforeRegex`，`rule.js:881`）。也就是说：

- 写在 `{{…}}` 里的 `##`（比如 JS 字符串里的 `"##"`）不会被误当成净化分隔符；
- `##` 之后的部分只做「正则/替换」解释，不再做模板展开。

**正例**：`{{$.title}}##\\s+##`（先插值，再净化）  
**反例**：`{{$.a##b}}`（JS 里真的要用 `##`）——虽然切点会跳过模板内部，但整串里一旦外面也有 `##`，两处混在一起时行为取决于哪一处先被当成切点，建议避开这种写法。

## 4. 各字段怎么写

下面每段都能直接抄。

### 4.1 搜索

```json
"searchUrl": "/search?q={{key}}&page={{page}}",
"ruleSearch": {
  "bookList": ".result-list li",
  "name": "h3 a@text",
  "author": ".author@text",
  "coverUrl": "img@src",
  "intro": ".intro@text",
  "lastChapter": ".last@text",
  "bookUrl": "h3 a@href"
}
```

要点：

- `bookUrl` 给相对地址即可，`resolveRuleUrl()` 会补成绝对地址，并且**保留 `,{…}` 选项后缀**（`legado.js:239-248`）。
- 封面会自动补绝对地址（`legado.js:545`），但也仅限 `ruleSearch.coverUrl` 与 `ruleBookInfo.coverUrl` 这两处。
- 分页：`<a,b,c>` 写法按页码取第 p 个（`rule.js:1526-1530`），`/search?q={{key}}&p=<1,2,3>` 会随 page 变化。

### 4.2 发现

`exploreUrl` 只支持三种形态（`legado.js:578-618`）：

```json
"exploreUrl": "玄幻::/x/{{page}}\n都市::/y/{{page}}"
```

```json
"exploreUrl": "[{\"title\":\"玄幻\",\"url\":\"/x/{{page}}\"},{\"title\":\"都市\",\"url\":\"/y/{{page}}\"}]"
```

```json
"exploreUrl": "/rank/{{page}}.html"
```

- 文本形态按**换行**或 `&&` 切（`legado.js:591`），`分类名::URL` 里 `::` 前面是标题，没有 `::` 就整段当地址。
- `{{page}}` 可用，发现页固定 page=1（`legado.js:657`）。
- **不要用 `@js:` / `<js>` 生成地址**：先会被 `&&`/换行误切，再因含 `@js:` 被拒，抛 `UNSUPPORTED`（`legado.js:613-615`）。
- 指定分类时，地址必须与 `exploreUrl` 里某条**完全相等**，否则报 `NO_RULE`（`legado.js:639`）。

### 4.3 详情（含 `init`）

HTML 站最常见的是「收窄到信息块」：

```json
"ruleBookInfo": {
  "init": "#info",
  "name": "h1@text",
  "author": ".author@text",
  "intro": "#intro@text",
  "coverUrl": "img@src",
  "tocUrl": "a.catalog@href"
}
```

`init` 之后，`name`、`tocUrl` 等规则都在 **`#info` 这个子树上**求值（`legado.js:774-784` 换掉 `ctx.node`）。

JSON 接口用 `init` 拆外层 + JS 返回对象：

```json
"init": "@js:JSON.parse(result).data",
"ruleBookInfo": {
  "name": "$.bookName",
  "author": "$.author",
  "intro": "$.intro",
  "coverUrl": "$.cover",
  "tocUrl": "$.catalogUrl"
}
```

`init` 返回对象后，其余字段按对象键取值（`legado.js:774-784`，对象会挂到 `ctx.value`/`ctx.json`）；返回字符串时会被当作内容再 parse 一次。

两种写法的差别：

- `init: "$.data"` —— 规则形态，走 `R.list` 取第一个结果（`legado.js:752`），节点/对象/字符串都保留原类型，是首选；
- `init: "@js:…"` —— JS 形态，返回值同样会被搬进上下文。

**`init` 以 `:` 开头（AllInOne 正则）会被跳过**，并在诊断里留一句「本轮未实现」（`legado.js:743-748`），不会抛错——但你的详情字段会全部取空。

### 4.4 目录

```json
"ruleToc": {
  "chapterList": "#list dd",
  "chapterName": "a@text",
  "chapterUrl": "a@href",
  "nextTocUrl": "a.next@href"
}
```

- 分页最多 20 页（`legado.js:903`，`maxTocPages` 配不动）；有防环（同地址不再抓，`legado.js:913`）。
- `nextTocUrl` 求出多个候选时，**只用第一个**（`legado.js:977`）；多地址写法（换行列表）在目录上没有意义。
- 目录页抓不到东西时，会自动改用书目页再试一次（`legado.js:984-987`），再不行就按内置选择器表猜一遍（`legado.js:1020-1021`，要求至少命中 5 个带 href 的 `<a>`）。

### 4.5 正文（含 `nextContentUrl`）

```json
"ruleContent": {
  "content": "#content",
  "nextContentUrl": "a.next-page@href"
}
```

- 正文最多 10 页（`legado.js:1073`），同样防环。
- `nextContentUrl` **可以给多个候选**：数组，或者换行分隔、或者含 `<js>`/`@js:` 的规则（`legado.js:879-892`）；候选数 >1 时会逐个抓（`legado.js:1150-1157`）。
- 抓下一页时会**按目录地址做边界过滤**：候选地址若属于别的章节，直接丢弃并停止（`stoppedBy='chapter-boundary'`，`legado.js:1137-1147`）。所以「下一页」指到下一章是安全的，不会串章。

## 5. JS 沙箱能力

### 5.1 三种 JS 写法

| 写法            | 谁执行 / 何时                                              | 返回值怎么被用                          | 依据                                                  |
| ------------- | ----------------------------------------------------- | -------------------------------- | --------------------------------------------------- |
| `@js:代码`      | `splitJsBlocks()` 切出一段 JS；`@js:` **之后整串都算 JS**，不再解析规则 | 作为本段结果，继续被后续段消费（段结果即新的 `result`） | `rule.js:972-985`、`rule.js:1257-1270`               |
| `<js>代码</js>` | 同上，但可以**夹在规则中间**：前面的文本段先求值，再跑 JS，再继续后面的段              | 同上，`result` 被替换                  | `rule.js:975`（正则里两个分支并列）                            |
| `{{表达式}}`     | 在规则内由 `makeUpRule` 逐字符展开；在 URL 里由 `expand()` 处理       | 插入到字符串里；**若整条规则只有模板，插值结果直接当答案**  | `rule.js:931-957`、`rule.js:1481-1524`、`rule.js:873` |

三者共享同一个沙箱 `NR.legacyJs.run(code, ctx)`（`rule.js:903`），也就是同一套 `java.*`。差别只在**执行时机**和**返回值消费方式**：`@js:`/`<js>` 交出的是「数据」（可为对象、数组、元素），`{{}}` 交出的是「字符串片段」。

`result` 的语义：进入 JS 时是本段的上游输入（元素会以 outerHTML 形式传入，`rule.js:903`）。脚本**没有 return 时，结果回退为进入时的 `result`**（`legacy-js.js:2379-2381`），`null`/`undefined` 归一成空串（`legacy-js.js:2429`）。

## 6. 不支持 / 有坑清单

这一节最该看。每条都写清「怎么写」「我们的行为」「怎么绕」。

### 6.1 请求选项 `,{…}` 只认 6 个键

写法：`"searchUrl": "/s?q={{key}},{\"webView\":true,\"method\":\"POST\",\"body\":\"k={{key}}\"}"`

我们的行为：`fetchPage()` 只显式读 `method`、`body`、`headers`、`charset`、`requestCharset`、`lenientDecode`（`legado.js:284-296`）。`webView`、`followRedirects`、`proxy`、`dnsIp`、`js`、`bodyJs` **完全不被读取**——不报错、不生效。`timeout` 选项也不认，只认书源级 `src.timeout`（`legado.js:308`）。

好的一面：`resolveRuleUrl()` 会把这个后缀原样拼回地址（`legado.js:239-248`），不会把 `{` `}` 编码坏，所以带这些选项的源不会因此崩，只是选项本身没作用。

建议：只写那 6 个键；要 POST 就显式 `"method":"POST"` + `"body":…`；需要更长的超时就写书源级 `timeout`（上限 30s）。

### 6.2 `header` 的三种形态，JS 出错静默退化

写法：`"header": "@js:JSON.stringify({...})"` 或 `"<js>…</js>"` 或纯 JSON 字符串。

我们的行为：`evalHeaders()` 先跑 JS 再 parse，**失败一律退化成 `{}` 且不抛错**（`legado.js:389-435`）。所以写错一个引号，表现是「请求头全丢、站点返回 403/验证页」，而不是语法错误。另外 `,{…}` 选项里的 `headers` 会**覆盖**书源级 `header` 的同名键（`legado.js:289-291`）。

建议：header 里别写复杂 JS；需要动态 token 时，先把它存进变量再拼 JSON 字符串，并在源里单独测一次搜索确认头真的发出去了。

### 6.3 `ruleBookInfo.init` 的边界

- 支持 `@js:`、`<js>`、`{{…}}`、以及普通规则（`$.data`、`#info`）（`legado.js:740-784`）。
- **`:` 开头的 AllInOne 正则形式会被跳过**，只留诊断（`legado.js:743-748`）。后果：详情字段全空，`tocUrl` 算不出来 → 退回当前页 → 可能 `EMPTY_TOC` → 整本判 dead。
- `init` 自己抛错也不会让详情失败，会回退到未预处理的页面（`legado.js:752-760`）——所以「init 写了但没生效」是静默的。

建议：一律用 `init: "$.data"` 或 `init: "#info"`；看到详情全空先怀疑 init。

### 6.4 目录下一页只取第一个地址

写法：`"nextTocUrl": "a.next@href\n#pages a@href"`（以为会依次试）

我们的行为：`catalog()` 拿到候选后 `pageUrl = candidates[0]`（`legado.js:977`），其余丢弃。求值抛错也不抛出去，只记诊断并停在第 1 页（`legado.js:968-975`）。

建议：目录分页只写一个选择器；如果站点有两种版式，用 `||` 而不是换行（`||` 取第一个非空，`rule.js:529`）。

### 6.5 发现页不要用 `@js:` / `<js>`

写法：`"exploreUrl": "@js:baseUrl + '/rank'"`

我们的行为：先按换行/`&&` 切分（`legado.js:591`，JS 里一旦有换行或 `&&` 就被切碎），随后命中 `@js:` 检测直接抛 `UNSUPPORTED`（`legado.js:613-615`）。筛选里它会被当成 `capability` 而不是普通失败。

建议：只写纯 URL、`分类名::URL`、或 `[{title,url}]` 三种（`legado.js:578-618`）。

### 6.6 沙箱缺口（写源时最容易踩）

| 写法                                                       | 我们的行为                                                 | 建议                                   |
| -------------------------------------------------------- | ----------------------------------------------------- | ------------------------------------ |
| `java.webView(...)`                                      | 抛 `UNSUPPORTED`（`legacy-js.js:2013`）                  | 项目整体不支持内置浏览器，改用纯 HTTP                |
| `java.getCookie/setCookie`、`cookie.getCookie`            | 抛 `UNSUPPORTED`（`legacy-js.js:2017-2019`、`2298-2302`） | cookie 不与会话共享；能拿到登录态只能靠 `header` 里写死 |
| `java.startBrowser*` / `getVerificationCode`             | 抛 `UNSUPPORTED`（`1996-2013`）                          | 无法过验证码，这类源不可用                        |
| `concurrentRate` / `isVip` / `loginCheckJs` / `loginUrl` | 字段不被读取（`legado.js:107-176`），**没有 CookieJar**          | 限速与登录态都做不了                           |
| `,{…}` 里的 `bodyJs` / `followRedirects`                   | 不读（`legado.js:284-296`）                               | 自己用 JS 拼 body；重定向由网络层自己处理            |

### 6.7 `bookSourceGroup` 被丢弃

写法：`"bookSourceGroup": "玄幻"`

我们的行为：`normalize` 里直接写 `group: ''`（`legado.js:122`），导入时读的是 `L.normalize(raw)`（`index.js:159`），所以这个键进不来。分组只能在软件内手动设置；已存在的源更新时会保留旧分组（`index.js:248`）。

> 说明：`index.js:636` 附近有一条注释提到「导入时 bookSourceGroup 带进来的」，与上面两处代码矛盾——以 `normalize` 的实际行为为准，注释应视为过期。

### 6.8 列表规则里的 `##` 不生效

写法：`"bookList": ".item##^广告$"`

我们的行为：`evalList` 只取 `##` 之前的部分当选择器（`rule.js:1272-1273`），`applyReplace` 只在 `evalString` 里调用（`rule.js:1246`）。所以净化被静默忽略。

建议：净化写在取值的子规则上（`name`、`intro` 这些走字符串路径的字段）。

### 6.9 `@CSS:选择器@text` 用在列表规则里会得到空项

写法：`"bookList": "@CSS:.item@text"`

我们的行为（代码推断，未运行验证）：`jsoupElements` 对 `@CSS:` 段取到元素后，若尾部有取值关键字，会把结果换成字符串（`rule.js:507`），而 `textToEl()` 恒返回 `null`（`rule.js:547`），于是列表项全是 `null`，后续每条的 `name` 都取不到 → `EMPTY_FIELDS`。

建议：列表规则用 `@CSS:.item`（不带取值）；确实要用 CSS 就写 `@CSS:` 然后不加 `@xxx`。

### 6.10 连接符混用只认第一个

`splitRule` 只按**最先出现**的分隔符切（`rule.js:257-266`）。`"a||b&&c"` → `["a", "b&&c"]`，`b&&c` 里的 `&&` 留在选择器里 → 0 命中。建议一条规则只用一种连接符。

### 6.11 搜索分页的界面行为（未确认）

`search(src, keyword, page)` 接受 `page` 参数（`legado.js:489`），URL 模板里 `{{page}}` 也会展开（`legado.js:491`）。但**阅读界面是否会请求第 2 页**，我未在渲染层找到对应调用——标为「未在本实现中确认」。写源时建议按「只翻第 1 页」设计，或者把更多结果塞进首页。

### 6.12 目录/正文的硬上限

目录 20 页（`legado.js:903`，且 `maxTocPages` 配不动），正文 10 页（`legado.js:1073`）。超过上限会停，诊断里 `stoppedBy='cap'`。长书拆成多页目录的站点会被截断。

### 6.13 其它零散坑

- **章节地址为空会被丢**：`if (!u) continue`（`legado.js:957`），不会给你留空章节。
- **`tocUrl` 解析出文字**（比如「查看目录」）会退回当前页（`legado.js:838-840`），不会当成地址。
- **非 UTF-8 的搜索参数**：`charset` 非 utf-8 时 query 会按字符集反推字节编码，**编不出的字符变成 `%3F`**（`rule.js:1750`），空格变 `+`。
- **`{{}}` 求值异常会抛错**（`rule.js:1515`、`rule.js:1506-1522`），不再静默空串——这是有意为之，因为静默空串会变成「搜不到书」。求值为 `null`/`''` 仍返回空串。
- **`.0` 与 `[0]` 不等价地「失败」**：越界一律钳制（`rule.js:352` 起），所以 `.5` 在只有 3 条时不会报错，而是返回空。
- **`java.put/get` 只在本轮有效**（`legacy-js.js:1295`），跨字段要用 `@put:`/`@get:`（存 `ctx.source.__vars`）。
- **`###` 会把结果裁成「只有第一个匹配段」**，不是「整串替换一次」，细节见 §3.5。
- **简化写法 `rules` 一旦写了 `bookSourceUrl` 就失效**（`legado.js:118` 的 `legado` 判定），地址得改成 `url`/`sourceUrl`，详见 §2.7。

## 7. 好不好用的自检方法

### 7.1 走一遍流程

1. **导入**：`importText()`（`index.js:224`）。导入时会顺手跑一遍静态能力检查（`capabilities.assess(raw)`，`index.js:158`），把「用了 `webView`/cookie/浏览器」之类的源标出来放进 `warnings`（`index.js:162-166`）。**先看这批警告**，能提前排掉一半注定跑不通的源。
2. **快筛**（并发 16、单源 6s、3 个关键词、1 章）：`deepTest({mode:'fast'})`（`online.js:1740-1744`）。
3. **慢筛**（并发 4、单源 30s、8 个关键词、3 章、允许重试）：`online.js:1744`。
4. **看日志**：文件名 `screen-fast-YYYYMMDD-HHmmss.log` / `screen-slow-…`（`online.js:1640-1650`），界面上有「筛选日志」按钮直接定位。日志**只记录非「可用」的源**，每条两行：`[时间] [中文判定] 源名 | 阶段 | 错误 | 源地址`，再加一行 JSON（含 `evidence`）（`online.js:1789-1796`）。
5. 筛选结束会自动清理失效源（`autoPurge`，`online.js:1804`）。

### 7.2 筛选的五个阶段（看懂日志里的「阶段」列）

- **L0 站点**：前面全是网络错时，补测一次书源首页，只写证据不改结论（`index.js:864-884`）。
- **L1 发现**：有 `exploreUrl` 就先跑发现页，上限 `min(6s, 预算/2)`；发现页失败只是跳过，不算失败（`index.js:891-912`）。
- **L2 搜索（用发现页的书名探针）**：失败记 `searchBroken`，但仍拿发现页的书继续验证（`index.js:914-939`）。
- **L3 搜索（兜底关键词）**：`重生、斗罗大陆、修仙、总裁、末世、三国、侦探、love`，整段 8s（`index.js:941-993`、`index.js:1387`）。
- **L4 书级**：前 3 条结果依次「详情 → 目录 → 正文」，正文按 1/2/3 章（首章 + 中间 + 末章）判定（`index.js:996-1074`）。

### 7.3 六种判定（日志里的中文标签）

| verdict      | 中文  | 含义                                             | 对源的影响                                   |
| ------------ | --- | ---------------------------------------------- | --------------------------------------- |
| `ok`         | 可用  | 全链路通过                                          | 写 `lastOk`，清空错误                         |
| `degraded`   | 降级  | 能用但有问题（正文偏短、首章不可读、搜索失效但发现页有书、前几本失败才成功）         | 写 `lastOk`，错误记为 `[降级] …`                |
| `noResult`   | 未搜到 | 请求正常但搜不到书                                      | **不写 `lastFail`**，不会因此被自动清理             |
| `dead`       | 失效  | 明确坏了：HTTP 404/410、`RULE`、`NO_RULE`、搜索结果里没有书籍链接 | 写 `lastFail`，`[失效] …`，可能被清理             |
| `unknown`    | 不确定 | 超时/网络/5xx/403/429/`BAD_JSON`/编码问题              | 写 `lastUnknown`，**不写 `lastFail`**，不会被清理 |
| `capability` | 不兼容 | 用了 `UNSUPPORTED` 的能力                           | 记 `[不兼容] …`，不当作站点失效                     |

依据：`finish()`（`index.js:844-862`）、`VERDICT_LABEL`（`online.js:1250`）、`screenTested`（`online.js:1690`）。
